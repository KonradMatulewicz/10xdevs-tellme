# Domain distillation — Tellme

Method: distillation from `context/foundation/prd.md` confronted with the code (`src/`, `backend/src/`). The repo is small (43 commits, one author) and surprisingly consistent in its language — unlike the lesson's classic "3×Account" example, the PRD and the code here mostly speak the same vocabulary. That's itself a result worth noting, not a reason to skip the analysis.

## Step 1 — Ubiquitous Language

| Term                    | Definition (PRD)                                                                      | Source quote                                                                                   | Where it lives in the code                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ----------------------- | ------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

Full analysis: `03-anti-corruption-layer.md`                                                                                                                                                                                                                                                                |

**A notable absence:** the PRD **does not** define any "generation session"-style entity with its own lifecycle (unlike the 10xCards example from the lesson). Tellme's flow is flat: recording → transcription → extraction → auto-save, with no intermediate state to manage. That isn't a gap — it's a deliberate, simpler domain shape, consistent with FR-008 (auto-save, "no manual save button," `prd.md:98`).

## Step 2 — Subdomain classification: Core / Supporting / Generic

| Area                                                                              | Category                    | Rationale (referencing the PRD)                                                                                                                                                                                                                                      |
| --------------------------------------------------------------------------------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Voice → Transcript → Task extraction (`backend/src/ai/*`, `routes/transcribe.ts`) | **Core**                    | This is the entire point of the product: "Eliminating that step is the product's entire value" (`prd.md:22`). The only area with no full research→plan cycle in the repo's history (confirmed in `context/map/artifact-3-contributors.md`) — despite being the core. |
| Task state management (todo/done/deleted, search)                                 | **Core**                    | US-02, FR-009 through FR-014 — the second half of "success = the whole flow working" (`prd.md:37`).                                                                                                                                                                  |
| Auth (email/password, Google OAuth, password reset)                               | **Supporting**              | Required ("table stakes," `prd.md:79`), but not what differentiates the product — a standard function supporting access to the core.                                                                                                                                 |
| Theming/UI primitives (`constants/theme.ts`, `themed-*`)                          | **Generic**                 | Zero domain logic, pure presentation — the highest fan-in in the repo (`context/map/artifact-2-structure.md`), but this is UI infrastructure, not domain.                                                                                                            |
| Supabase/Cloudflare Workers AI/Anthropic integrations                             | **Generic** (well isolated) | External SDKs, well sealed inside `ai/transcribe.ts`/`ai/extract.ts` (confirmed in `voice-task-pipeline/research.md`, zero vendor-type leakage into the router).                                                                                                     |

## Step 4 — MODEL vs CODE drifts

| The document says                                                                                                           | The code does                                                                                                              | Evidence                                                                                                            | Assessment                                                                                                                                                                                                                                                                                                                      |
| --------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-007: "User can review and inline-edit extracted tasks before they are saved" (nice-to-have, an optional pre-save screen) | Zero pre-save screen — `POST /transcribe` always auto-saves immediately after extraction, with no confirmation step at all | `backend/src/routes/transcribe.ts:47-53` (the insert follows `extractTasks` directly, no intermediate state at all) | **Not a drift in the sense of a bug** — the PRD explicitly marks FR-007 as nice-to-have and says "happy path auto-saves (FR-008)... FR-007 is an optional non-blocking review step" (`prd.md:95`). The code simply never implemented the optional part. Worth writing down explicitly so nobody assumes a review screen exists. |
| `TaskStatus`/`TASK_STATUSES` — one domain entity                                                                            | Two independent, hand-maintained copies (`src/types.ts`, `backend/src/types.ts`)                                           | `context/map/repo-map.md`, `context/changes/voice-task-pipeline/research.md`                                        | A code-vs-code drift, not PRD-vs-code (the PRD doesn't mention the type's representation) — but exactly the kind of quiet risk this lesson is about: nothing today enforces agreement.                                                                                                                                          |
| Business Logic (extraction)                                                                                                 | The SYSTEM prompt in `extract.ts`                                                                                          | `prd.md:120-124` vs `extract.ts:12-20`                                                                              | **No drift — a positive confirmation.** A rare case where the code and the document say almost identical words.                                                                                                                                                                                                                 |

## Step 5 — Ranking for further work

1. **#1 — The invariant "task text is never empty," enforced twice independently.** Core (concerns `Task`), weakly enforced (two copies of the rule, no shared one), and — importantly — **naturally converges with C1 from `context/changes/refactor-opportunities/plan.md`** (the `insertTasks()` function being extracted there is a ready-made place to be the single enforcement point). Full plan: `02-invariant-aggregate-refactor.md`.
2. **#2 — `exchangeCodeForSession` called directly from `reset-password.tsx`, bypassing the `auth.tsx` port.** Auth logic duplication with different error handling than `signInWithGoogle`. Full plan: `03-anti-corruption-layer.md`.
3. **#3 (lower priority, not written up as its own document) — `TaskStatus` duplication.** Already analyzed as candidate C2 in `context/changes/refactor-opportunities/research.md` (deferred by the user in this planning round) — not duplicating that analysis here.

**Summary (5-8 sentences):** This document built Tellme's domain vocabulary from the PRD confronted with the code, and found it surprisingly consistent — no classic "3×Account." The biggest value of this analysis isn't discovering naming chaos, but two concrete, evidence-grounded places where a business rule exists but is enforced in more than one place at once: the empty-task-text invariant (two copies) and the OAuth-code/reset exchange operation (two copies, with diverging error handling). Both have a ready landing spot in already-planned L4 work (`insertTasks()`). The third, weaker drift — the missing optional FR-007 screen — is a documented, deliberate gap in the PRD, not a bug. The most important takeaway: this repo doesn't have a vocabulary problem, it has a problem with the number of places the same vocabulary is enforced in.
